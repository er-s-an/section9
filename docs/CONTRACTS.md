# Section9 integration contract v1 (owner: root)

All timestamps are UTC ISO strings; revision/generation/epoch serialize as decimal strings. Python 3.12+, FastAPI; frontend React/Vite/TypeScript. Shared schema, dependency/lock files, DB and root config are ROOT ONLY. Do not access .env or CLAIMS.md in coding-agent tasks. No key values in outputs.

JSON errors: `{error:{code,message}}` (handle FastAPI `detail` too). Every mutation returns JSON. Frontend must render real responses and refetch; no timed fake transitions. ## Victim Python interface

`class VictimApp` constructor `VictimApp(model, get_config, emit)`:
- model: async `await model.complete(messages:list[dict], *, run_id:str|None=None, purpose:str="victim", max_tokens:int=512) -> dict` with keys `content:str, usage:dict, elapsed_s:float, model:str, trace_id:str|None`. It is real provider backed; injectable test double only in component tests.
- get_config: sync callable returns `{revision,generation,prompt_version,context_multiplier,max_output_tokens,retry_limit,retry_on_terminal}`. Must check generation and cancellation at tool-call boundaries.
- emit: async callable `(event_type:str,payload:dict,*,run_id=None,producer="victim") -> dict|None`.
- `await chat(message:str, *,run_id:str|None=None, purpose:str="user", request_id:str|None=None) -> dict` with API result fields. Track tool calls/progress and actual usage. Config selected at start; revision reported accurately. Context multiplication really modifies sent content. A terminal tool error + retry_on_terminal produces real repeated tool calls with bounded safety cap; loop must be cancellable on config/reset. Do not call provider repeatedly unbounded.
- `await probe(*,suite="detect"|"verify",run_id=None) -> dict` returns `{passed,checks:[{name,passed,expected,actual,request_id}],requests:[],tested_revision,usage,elapsed_s}`. Separate cases for detection/verification; at least an unaffected product-fact check for verification, correct semantics plus no active stalled loop and budget controls. Do not mark healthy via config alone; business checks use real model output.
- `cancel_all(reason:str="reset") -> int` sync; `status() -> dict` sync includes active_requests,stalled_requests,total_tool_calls,last_requests (bounded).
- `healthy_config() -> dict` module-level returns prompt_version healthy, context_multiplier1, max_output_tokens1536,retry_limit3,retry_on_terminal false.
- Probe may parallelize up to 2 real requests via model global semaphore. Check current revision still equals tested revision at end; root additionally CAS-closes. Prompt originals preserved; explicit structured-output request added by runtime. Do not fabricate answers for model failures.

## Telemetry Python interface

`class Telemetry` constructor `Telemetry()` reads environment (never logs secrets). `record(name:str, *, start_ns:int,end_ns:int,input_data:dict|str,output_data:dict|str,metadata:dict,usage:dict|None=None) -> str|None` creates complete OTel/Langfuse span and returns 32-hex trace id. `async health() -> dict`; `flush()` shutdown. Collector endpoint configured via env. Must be safe when dependency absent, explicit health/degraded status. Trace export separate from local authoritative control events. Infra should provide OTel Collector fanout -> backend `http://host.docker.internal:9019/api/telemetry/v1/traces` and Langfuse; backend implemented by root accepts OTLP protobuf or JSON. Root additionally processes independent live progress events (not waiting for span end).

## Local safety and capabilities

Local business control uses SQLite WAL and BEGIN IMMEDIATE transactions for one-machine consistency (adaptation from proposed PostgreSQL to reduce resource use; immutable revision+fencing checked in same transaction). No external network or model in a transaction. Worker role auth is bound by server token; workers never get model provider key. Operator endpoints are localhost-only. Agent context cannot read operator SSE/full logs, current-run memory, scenario ground truth or other-role conclusions outside CollaborationPort. Public operator UI is explicitly a privileged console.

## Worker HTTP API (root implemented; roles in separate OS processes)

CLI `python -m s9.workers --id sentry|diagnoser|fixer-a|fixer-b|verifier|cost|single --base-url http://127.0.0.1:9021`. Token via process env S9_AGENT_TOKEN (root launches). Every request Authorization Bearer. All JSON endpoints below are under `/agent` and scoped by token. Do not access operator /api endpoints, database, .env, raw log files, scenario ids or truth fixtures.

- GET `/agent/context` -> `{id,role,paused,generation,config,observations:[{id,type,summary,payload}],incident:null|{id,run_id,status,opened_at,condition},tasks:[{id,kind,status,epoch,holder}],messages:[{id,sender,kind,content,evidence_ids,confidence}],plan:null|{id,status,actions,expected_revision},last_action:null|{id,revision},memory:null|playbook}`. Config is role-projected: diagnoser sees prompt+known_good_prompt; fixer sees context/retry values and known_good policy; single sees union. No scenario, no other-role reasoning except messages. Sentry sees observations only and is deterministic. Verifier sees frozen acceptance contract and action but no private reasoning. `paused` means worker must heartbeat and wait; if it already has grant it must preserve it for resume/replay. Worker budget/lease timeout server enforced.
- POST `/agent/heartbeat` `{status,detail,task_id?}` -> `{ok,paused}`.
- POST `/agent/incidents` `{observation_ids:[string]}` (sentry): server derives symptoms from observed facts; creates initial tasks. No caller-supplied ground truth.
- POST `/agent/claim` `{task_id}` -> `{task_id,epoch,lease_deadline,run_id}` or 409. Worker autonomously selects open capability-matching task, reclaims expired task.
- POST `/agent/renew` `{task_id,epoch}` -> `{ok}` or409. Workers renew while model awaiting using own heartbeat loop; paused stops renewing. Lease ~8s.
- POST `/agent/message` MessageRequest.
- POST `/agent/model` ModelRequest -> Model.complete result. max concurrent2 and global per-run budget. Content should request JSON root cause/proposed config; handle malformed response by one repair retry max.
- POST `/agent/plan` PlanRequest -> `{id,hash,status}`; fixer/single only. Values allow prompt_version healthy|degraded,context_multiplier1..8,max_output_tokens64..4096,retry_limit0..6,retry_on_terminal bool. Plan must repair observations, not ask to disable chaos. Worker LLM picks actions; do not map scenario to canned fix.
- POST `/agent/grant` `{plan_id}` -> `{grant_id,...}` or `{error:{code:APPROVAL_REQUIRED|POLICY_DENIED,...}}`. For fencing script, response may contain `pause_before_execute:true`; worker must wait while context.paused and later send ORIGINAL grant (do not refresh), causing actual stale rejection. Normal pause also preserves obtained grant.
- POST `/agent/execute` ExecuteRequest -> `{action_id,revision,status}`. Stale rejection gets logged; then abandon old plan and resume discovery.
- POST `/agent/verify` `{run_id}` verifier/single only -> actual external probe checks + CAS close, may return `{passed:false,...}`. Verifier should only request after last_action exists. For single baseline this is same deterministic independent test service, not a self-judgement.
- POST `/agent/task/complete` `{task_id,epoch,result_summary}` -> `{ok}`.

Default roles: sentry kind detect; diagnoser kind diagnose; fixer-a and fixer-b kind repair; verifier kind verify; cost kind cost; single kind single. On normal run, primary fixer should have slight poll lead (standby delay0.8s) but no hardcoded dispatch. Workers independently read/claim. Diagnoser model produces hypothesis and sends a challenge/build_on/synthesize message. Fixer waits for diagnoser conclusion while collecting own observations; when muted, the same repair capability remains available but only its own projected observations are readable; it may attempt a repair or abstain, and no failure is forced. Once a plan applied, verifier independently calls verify. Single bypasses peer dependency and uses UNION same available facts/tools/model/budget. Context.condition selects applicable runtime roles (baseline disables normal diagnose/repair/verify workers for that run). After successful completion worker returns idle; no infinite model retries. Cost joins capability directory at runtime, gets actual cost task when an incident exists, read-only analysis and message, no execute right.

Model calibration: GLM includes reasoning in completion budget. Healthy max_output_tokens is 1536, injected cost cap4096; worker completion cap1600. Values are recorded in manifests, no hidden upward override.
