## 审查后修正

- 原问题断言需要涵盖每个明确查询意图，状态与资格组合不能只验资格。
- 验证报告、执行尝试、恢复回执必须引用同一预案和同一次执行。
- 回退有独立回执；读回旧策略仅说明回退完成，不说明业务恢复。
- 无效数据库快照、未知执行结果、模型失败均不能生成绿色恢复结果。
- 新配置升级保留保护策略和旧证据，重新绑定实际源码，不跨版本沿用旧审批。

## 真实压力测试的首轮失败

本机报告 `.runtime/demo-validation/20260923-211710-adversarial.json`，15 个 live 用例逐个执行，没有自动重试；当时 adapter 为 `ecbf70c7f649af6b5cb0bbdcc2b38c3a83a44cf7`。脚本原结果为 13 passed / 2 failed，另 2 个 mock case 未在 live 运行。全部业务数据库前后摘要一致、来源与配置绑定一致。

本轮据此修正业务分类与测试断言，再单独对新版执行完整真实用例。最终结果见后续记录，不能用后续成功覆盖这次失败。
