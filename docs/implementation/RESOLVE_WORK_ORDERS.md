## 唯一目标

在现有 `/demo` 内，让一个真实业务任务经过观察、调查、建议审核、具体动作授权、受控处理、结果核对、独立业务验证和经验候选。用户可自由输入，业务数据仍是隔离的本地演示数据。先完成 support-agent 一个预定义配置 Runbook，不承诺任意代码自动修复或完整 CloudThinker 平台。

基线：`9daf9fc` 是已推送的调查演示；`791544a` 是本地橙黑像素 UI。开始时仅有预先存在的 `frontend/test-results/` 未跟踪。发行前必须重新核实远端。

## 共用边界

- 继续复用 ProductRegistry 的 Workspace/Application/Incident/InvestigationRun/Evidence/Task、原生 EvoMap 会话、ExternalRuntime、已有执行与恢复契约；不创建第二个事故权威源。
- 保留原 React、OfficeScene、Star Office 和橙黑素材。网页状态来自 API，不能用动画或预设答案伪造协作、执行或恢复。
- 调查建议认可与具体修改授权分开。执行绑定不可变方案 hash、目标版本、原配置、动作和操作者；配置改变后旧授权失效。
- 初次接管保留实际旧路由配置；只在用户批准后切换保护策略。升级后的保护保持启用，不为展示反复偷偷恢复故障。
- 默认只读业务演示，退款/付款工具不能因 prompt injection 被执行；未接人工队列不得声称真人已接单。
- 真实调用允许；失败、未知用量和中断均保留。隔离运行产物留在 `.runtime`，不得提交凭据、数据库、依赖目录或整包报告。

## 集成顺序

1. 固定 T1/T3/前端接口；实现与模拟回归可并行，禁止多个 Agent 同时改共享运行目录或重启服务。
2. 主导者检查 diff，补接配置/互斥/观察筛选。保留不确定态；正常人工请求、澄清和安全拒绝不自动当事故。
3. 备份本机状态，安装可重复 overlay，重启自己拥有的 9160/9150 服务；不影响历史 9019。
4. 在浏览器真实发起自由问题、观察上下文和协作，审核实际动作、执行并核验；在同一事故下记录全部结果。
5. 顺序跑刁钻输入和故障回归，修复真实失败，再由主导者检查至少一条用户可见完整路径。记录限定样本，不能由测试通过推断所有输入正确。
6. 保留一个已成功闭环任务及正常可玩的运行环境；交接启动、操作、失败出口和源码/运行版本。精确暂存源码和去敏文档，push 后核验远端 SHA。

## 完成定义与回退

- 第一个事故必须包含新输入、应用 trace、角色调查、独立动作授权、实际配置执行、目标配置回读、独立业务回归、连续健康观察、业务 DB 无意外变更及历史。
- 误报/证据不足/工具失败/执行未知必须能明确停止或继续，不把它们染成绿色。
- 经验先作为待审候选，不自动发布 Hub。后续调查能引用已批准经验才算验证复用。
- 蜂群质量优势需要同证据盲评；不得用新增角色数量、native 消息数量或故障演练冒充质量胜出。
- 失败回退仅恢复明确批准的旧策略；保留旧新配置、执行和验证记录。代码回退保留数据库备份，不 reset 共享工作树，不删除历史。
- 本轮未承诺：任意代码补丁、跨机器自治、多租户/公网安全、全部横向模块、完整动态规划、长期生产观察。
